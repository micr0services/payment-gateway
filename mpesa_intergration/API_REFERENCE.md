## B2C (Business to Consumer)

Send money from business account to customer accounts.

### Send Money
```http
POST /api/b2c/send
Content-Type: application/json
```

**Request Body:**
```json
{
  "mobileNumber": "0712345678",
  "amount": 100,
  "description": "Salary Payment"
}
```

**Response (Success):**
```json
{
  "success": true,
  "transactionId": "uuid-here",
  "mpesaResponse": {
    "ConversationID": "mpesa-conversation-id",
    "OriginatorConversationID": "originator-id",
    "ResponseDescription": "Accept the service request successfully",
    "ResponseCode": "0"
  }
}
```

### Get Transaction Status
```http
GET /api/b2c/status/{id}
```

where `{id}` can be any of:
- **`transactionId`** (from send response) - internal system UUID
- **M-Pesa `OriginatorConversationID`** - echo of what we sent to M-Pesa
- **M-Pesa `ConversationID`** - unique reference generated by M-Pesa  (`AG_...`)

**Example using M-Pesa ConversationID:**
```http
GET /api/b2c/status/AG_20260313_0100102806qwploaz5yg
```

**Response:**
```json
{
  "success": true,
  "transaction": {
    "id": "uuid-here",
    "transactionType": "B2C",
    "status": "PENDING",
    "mobileNumber": "0712345678",
    "amount": 100,
    "conversationId": "conversation-id",
    "createdAt": "2024-01-15T10:30:00Z",
    "updatedAt": "2024-01-15T10:30:00Z"
  }
}
```

```json
    "ConversationID": "mpesa-conversation-id",
```

Prompt customers to enter M-Pesa PIN or check status.

### Initiate STK Push
```http
POST /api/stk/push
Content-Type: application/json
```

**Request Body:**
```json
{
  "mobileNumber": "0712345678",
  "amount": 500,
  "accountReference": "ORDER-001",
  "transactionDescription": "Purchase Payment"
}
```

**Response (Success):**
```json
{
  "success": true,
  "transactionId": "uuid-here",
  "checkoutRequestId": "ws_CO_123456789",
  "mpesaResponse": {
    "MerchantRequestID": "merchant-id",
    "CheckoutRequestID": "ws_CO_123456789",
    "ResponseCode": "0",
    "ResponseDescription": "Success"
  }
}
```

### Query STK Push Status
```http
POST /api/stk/query
Content-Type: application/json
```

**Request Body:**
```json
{
  "checkoutRequestId": "ws_CO_123456789"
}
```

*Note:* only use the ID returned by `/stk/push`. The transaction may not be
immediately available for query (give it a second or two) and IDs expire quickly in the
sandbox; if the API cannot find the resource you will receive an error. Our implementation
returns a helpful message instead of propagating the raw 404.

**Response:**
```json
{
  "success": true,
  "transactionId": "uuid-here",
  "mpesaResponse": {
    "ResponseCode": "0",
    "ResultCode": "0",
    "ResultDesc": "The service request has been processed successfully"
  }
}
```

### Get Transaction Status by Conversation ID
```http
GET /api/stk/status/{conversationId}
```

## Transactions

Query and analyze all transactions.

### Get All Transactions
```http
GET /api/transactions/all?page=1&limit=10&type=B2C&status=SUCCESS
```

**Query Parameters:**
- `page` (optional): Page number for pagination (default: 1)
- `limit` (optional): Number of records per page (default: 10, max: 100)
- `type` (optional): Filter by type - B2C, C2B, B2B, STK_PUSH, STK_QUERY, REVERSAL
- `status` (optional): Filter by status - SUCCESS, PENDING, FAILED

**Response:**
```json
{
  "data": [
    {
      "id": "uuid-here",
      "transactionType": "B2C",
      "status": "SUCCESS",
      "mobileNumber": "0712345678",
      "amount": 100,
      "mpesaTransactionId": "KBL2...",
      "mpesaReceiptNumber": "LHM7...",
      "resultCode": 0,
      "resultDesc": "Success",
      "createdAt": "2024-01-15T10:30:00Z",
      "updatedAt": "2024-01-15T10:31:00Z"
    }
  ],
  "pagination": {
    "total": 150,
    "skip": 0,
    "take": 10,
    "pages": 15
  }
}
```

### Get Transaction by ID
```http
GET /api/transactions/{id}
```

**Response:**
```json
{
  "id": "uuid-here",
  "transactionType": "B2C",
  "status": "SUCCESS",
  "mobileNumber": "0712345678",
  "amount": 100,
  "description": "Salary Payment",
  "conversationId": "conversation-id",
  "originatorConversationId": "originator-id",
  "resultCode": 0,
  "resultDesc": "Success",
  "mpesaTransactionId": "KBL2...",
  "mpesaReceiptNumber": "LHM7...",
  "requestPayload": { /* ... */ },
  "responsePayload": { /* ... */ },
  "callbackPayload": { /* ... */ },
  "createdAt": "2024-01-15T10:30:00Z",
  "updatedAt": "2024-01-15T10:31:00Z"
}
```

### Get Transactions by Type
```http
GET /api/transactions/type/{type}?page=1&limit=10
```

**Path Parameters:**
- `type`: Transaction type (B2C, C2B, B2B, STK_PUSH, STK_QUERY, REVERSAL)

**Query Parameters:**
- `page` (optional): Page number for pagination (default: 1)
- `limit` (optional): Number of records per page (default: 10, max: 100)

**Response:** (Same as Get All Transactions)

### Get Transactions by Status
```http
GET /api/transactions/status/{status}?page=1&limit=10
```

**Path Parameters:**
- `status`: Transaction status (SUCCESS, PENDING, FAILED)

**Query Parameters:**
- `page` (optional): Page number for pagination (default: 1)
- `limit` (optional): Number of records per page (default: 10, max: 100)

## Webhooks/Callbacks

Handle real-time updates from M-Pesa.

### C2B Callback
```http
POST /callbacks/c2b
Content-Type: application/json
```

This endpoint is called by M-Pesa when a customer makes a payment.

### B2C Callback
```http
POST /callbacks/b2c
Content-Type: application/json
```

This endpoint is called by M-Pesa when B2C transaction completes.

### STK Callback
```http
POST /callbacks/stk
Content-Type: application/json
```

This endpoint is called by M-Pesa when STK Push is completed.

### Reversal Callback
```http
POST /callbacks/reversal
Content-Type: application/json
```

This endpoint is called by M-Pesa when reversal transaction completes.

### Get Webhook Logs
```http
GET /callbacks/logs?skip=0&take=10
```

**Response:**
```json
{
  "data": [
    {
      "id": "uuid-here",
      "eventType": "c2b",
      "processedStatus": "PROCESSED",
      "errorMessage": null,
      "payload": { /* ... */ },
      "createdAt": "2024-01-15T10:30:00Z"
    }
  ],
  "pagination": {
    "total": 50,
    "skip": 0,
    "take": 10,
    "pages": 5
  }
}
```

## Error Responses

All endpoints follow this error response format:

```json
{
  "error": "Error message description",
  "status": 400
}
```

### Common Error Codes
- `400` - Bad Request (missing required fields, invalid input)
- `404` - Not Found (transaction not found)
- `500` - Internal Server Error (server-side issue)

---

## Request Headers

All requests should include:
```
Content-Type: application/json
```

## Rate Limiting

Currently there are no rate limits. In production, implement:
- Request throttling per IP
- API key authentication
- Rate limits: 100 requests per minute per user

---

## Authentication

Currently, endpoints are open. In production, add:
- API Key authentication
- Bearer token authentication
- OAuth 2.0

---

## Pagination

For list endpoints, use these query parameters:
- `skip`: Offset from start (default: 0)
- `take`: Number of records to return (default: 10, max: 100)

Response includes pagination info:
```json
{
  "data": [ /* ... */ ],
  "pagination": {
    "total": 150,
    "skip": 0,
    "take": 10,
    "pages": 15
  }
}
```
